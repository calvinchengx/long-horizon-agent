# The UI API contract

`openapi.json` (OpenAPI 3.1) is the only definition of the API every implementation's `lha serve`
provides to the mission UI and MCP clients ([docs/27-mission-ui.md](../../docs/27-mission-ui.md)).
It is written before server code; a server is built to pass it.

| File | What |
|---|---|
| `openapi.json` | operations, request and response schemas, security; `MissionEvent` payloads `$ref` [`../obs/mission_events.json`](../obs/mission_events.json) |
| `fixture.json` | the store rows and anchors every case runs against (generated by `python/scripts/export_spec.py`) |
| `cases.json` | one case per behaviour: a request and its expected status, error code and body |
| `check-breaking.sh` | fails when `openapi.json` breaks a client of a base commit's API within the same major version |

## Coverage

- **Static, in every unit run** (`test_every_ui_api_operation_and_status_has_a_case`): every
  operation and every response status it documents has a case; every case names a documented
  operation, path and status; the fixture records every event kind.
- **Against a running server** (`python/tests/serve/`): every case's response matches its status,
  its error code and its body, and validates against the operation's response schema (so every
  recorded event is checked against its kind's schema). CI runs it against each implementation's
  server, once with Temporal unreachable and once with a fake mission workflow.
- **No undocumented routes**: each implementation tests that the routes it registers are exactly
  the paths in `openapi.json`, and an unknown `/api/` path is a 404 `not_found`.
- **No breaking change**: within a major version (`info.version`) the API only grows. CI runs
  `check-breaking.sh <base>` (oasdiff) against the previous commit's or a pull request's base's
  contract; removing or renaming anything a client reads, or requiring anything new, fails it.
  Linted with Redocly.

## What a server must do to be tested

The runner starts the server with `<command> --host 127.0.0.1 --port 0` and this environment:

| Variable | Meaning |
|---|---|
| `LHA_SQLITE_PATH` | the seeded mission store (`LHA_POSTGRES_DSN` is unset) |
| `LHA_SERVE_TOKEN` | the token to accept (otherwise the server makes a random one) |
| `LHA_TEMPORAL_ADDRESS` | Temporal: unreachable, or a dev server running the fake workflow |

Its first line on stdout is `lha serve: http://127.0.0.1:<port>/?token=<token>`.

## Cases

```json
{"name": "...", "operation": "listEvents",
 "request": {"method": "GET", "path": "/api/v1/missions/mission_local/events",
             "query": {"limit": "2"}, "auth": "header", "host": "...", "headers": {}, "body": {}},
 "expect": {"status": 200, "body": {...}, "error": "not_found", "signal": {...}, "stream": {...}},
 "temporal": "absent"}
```

- `auth`: `header` (the default: `X-LHA-Token`), `cookie` (`lha_token`), `none`, or `wrong`.
- `host`: the `Host` header to send instead of the server's own.
- `body`: JSON, or `"$not-json"` for a body that does not parse.
- `expect.body` is a subset of the response: objects match key by key, a list matches element by
  element and in length, `"$any"` matches any value, `{"$len": n}` a list of length `n`, and
  `{"$contains": [...]}` a list holding an element matching each one.
- `expect.error` is the `error.code` of an error response.
- `expect.signal`: the signal the fake workflow must have received (`{"name": "$cancel"}`: the
  workflow was cancelled).
- `expect.stream`: the first `mission_event` messages of a Server-Sent Events stream, in order.
- `temporal`: run only with Temporal `absent` or the fake workflow `running`; no value runs in both.
